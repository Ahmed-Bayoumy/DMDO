Disciplines#

class DMDO.Discipline(*args, **kwargs)#

Bases: Protocol

A disciplinary analysis.

compute receives the analysis inputs keyed by variable name (scalars or arrays) and returns a mapping that contains every output variable of the analysis, keyed by name. Implementations may also expose input_names / output_names sequences for validation, but they are not required.

Example adapter around a model from another framework (kept in user code, not in DMDO):

class ExternalModelDiscipline:
  def __init__(self, model, inputs, outputs):
    self.model, self.input_names, self.output_names = model, inputs, outputs
  def compute(self, inputs):
    for name in self.input_names:
      self.model.set_input(name, inputs[name])   # whatever the framework's API is
    self.model.evaluate()
    return {name: self.model.get_output(name) for name in self.output_names}

class DMDO.SubproblemSolver#

An optimizer for one subproblem (a protocol; subclass BaseSolver to implement one).

objective_form#

"vector": request.objective(x) returns [f + penalty, [g1, g2, ...]].

solve(request)#

Optimize the subproblem described by request (a SolverRequest) and return a SolverOutcome.

report_hmin(hmin)#

The constraint violation of a solve in the form recorded by the coordination loop (identity by default).

class DMDO.SolverRequest(name, objective, constraints, x0, lb, ub, var_names, var_types, var_sets, constants, constants_names, budget, budget_scale, seed, iteration, tol=1e-12, display=False, post_dir=None, config=None, warm_start=<factory>)#

Bases: object

Everything a solver needs to optimize one subproblem.

objective(x, *args) evaluates the augmented subproblem at x. Its return value has the form the solver declared via SubproblemSolver.objective_form: "vector" -> [f + penalty, constraints], "scalar" -> a single penalized float. constraints(x) returns the inequality constraint values (g <= 0).

Executors#

class DMDO.Executor(*args, **kwargs)#

Bases: Protocol

Runs independent tasks and returns their results in task order.

The coordination loop hands an executor DMDO.workflow.execution.SubproblemTask messages together with the module-level function that solves one (DMDO.workflow.execution.solve_task()). Local executors call it in this process or in worker processes; a remote executor (an HTTP/gRPC/queue client, a Ray or Dask cluster, …) ships the pickled task to a worker that calls the same function. Whether subproblems see each other’s updates within an outer iteration is decided by the coordination sweep, not by the executor.

Register an implementation with DMDO.registry.executors.register("name", factory) (or via the dmdo.executors entry-point group); the factory is called as factory(max_workers=n).

Observers#

class DMDO.RunObserver#

Hooks called by the coordination loop. Subclass and override the hooks you need; every hook is optional, and any object that defines some of them can be used as an observer. run is the MDO object: read its state (run.Coordinator, run.subProblems, run.fmin, …) rather than keeping references to it. Observers are called in the order they are given, after DMDO’s own, and are not pickled into checkpoints.

on_run_start(run)#

Once, before the first outer iteration.

on_iteration_start(run, iteration)#

Before the subproblems are solved.

on_resume(run, iteration)#

Instead of on_iteration_start for the first iteration of a run resumed from a checkpoint.

on_sweep_end(run, iteration)#

All subproblems solved and the inconsistencies computed, before the penalty update.

on_iteration_end(run, record)#

The iteration is final for reporting; record is an IterationRecord.

on_multipliers_updated(run, iteration)#

After the multipliers and penalty weights were updated, before the stopping test.

on_run_end(run)#

Once, after the last outer iteration (not called when the run raises).
