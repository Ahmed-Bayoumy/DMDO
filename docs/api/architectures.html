Hierarchical ATC#

Hierarchical analytical target cascading (architecture: {DIST: {IDF: ATC}}).

The subproblem with is_main: True is the system-level element (the root). The other subproblems hang below it through the variable links: the subproblems linked to the root are level 1, the subproblems linked to those (other than their parent) are level 2, and so on. The links must form a tree, so that every target/response pair connects a parent to one of its children; a cycle (for example three subproblems linked to each other) is rejected.

The relaxation and the multiplier updates are the ADMM coordinator’s (augmented Lagrangian v q + |w q|^2, method of multipliers): ATC with ADMM is the alternating-direction variant of Tosserams et al. (2006), with one pass over the hierarchy per outer iteration. Each outer iteration solves the hierarchy level by level from the root down; the subproblems of one level share no pairs, so they are solved as one batch (in parallel with a parallel executor) from the same coordinator state.

Monolithic MDF#

Monolithic MDF (architecture: {MON: MDF}).

Every subproblem is a standalone MDO problem: its variables may not be linked to other subproblems. Its solver (solver, scipy / configurations, budget keys, unchanged) optimises the subproblem’s design variables directly. At every evaluation the subproblem’s MDA converges its feedback loops (MDA.<id>.solver, default GS; see DMDO.analysis.mda_solvers), then opt(x, y) gives the objective and the constraints g <= 0. The bounds of the MDA responses are added as constraints, as the distributed path does for its couplings. An evaluation whose MDA does not converge is reported as failed (objective +inf).

There is no coordinator: subproblems are solved one after the other, independently.

MDA feedback detection and solvers#

Feedback detection and fixed-point solvers for a multidisciplinary analysis (used by MON: MDF).

Feedback detection

Inside one MDA block, analysis A feeds analysis B when a variable key in A’s outputs is also in B’s inputs (matched by the variable’s unique index, never by name). The strongly connected components of that directed graph (Tarjan) are the feedback loops: a component with two or more analyses, or an analysis that reads its own output. Only those are handed to the MDA solver; the rest is feed-forward and runs once, in dependency order.

Solvers (MDA.<id>.solver: a name, or a mapping {name: ..., tol: ..., maxiter: ...})

GS Gauss-Seidel fixed point: each analysis uses the latest outputs of the others (default). Jacobi Jacobi fixed point: every analysis of a sweep uses the outputs of the previous sweep. Newton Newton’s method on the residual R(y) = y - F(y), finite-difference Jacobian, backtracking step.

Options: tol (default 1e-10) on the scaled residual max_i |y_i - F_i(y)| / max(1, |y_i|), maxiter (default 100), relaxation (GS/Jacobi, default 1.0: y <- y + relaxation (F(y) - y)), fd_step (Newton, default 1e-7, relative).
