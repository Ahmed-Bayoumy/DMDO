Coordination loop and execution#

MDO#

class DMDO.MDO#

The multidisciplinary design optimization process: the coordinator, the subproblems, the variable copies and the records of a run (fmin, hmin, tab_inc with the maximum inconsistency of every outer iteration, stop with the stopping reason). Built by build_mdo() or directly with the Python API (The Sellar problem).

MDO.run(file=None, resume=False, mode=None, executor=None, sweep=None, max_workers=None, observers=None)#

Run the coordination loop to the end.

Parameters:

  • mode – "serial" (default sweep Gauss-Seidel, in-process) or "parallel" (default sweep Jacobi, process pool with one worker per subproblem); default: the coordinator’s mode from the problem definition.

  • executor – an Executor instance or a registered executor name ("inprocess", "process" or a plugin) that runs the subproblem solves; overrides the one implied by mode.

  • sweep – "gauss_seidel" or "jacobi"; overrides the one implied by mode.

  • max_workers – worker count for executors created from a name (default: number of subproblems).

  • observers – RunObserver objects notified during the run, after DMDO’s own observers.

To drive the loop step by step, or to solve the subproblems yourself (ask/tell), use DMDO.Session.

With architecture: {MON: MDF} every subproblem is solved on its own by monolithic MDF instead (no coordination; file, resume, mode, executor, sweep and max_workers do not apply) and the per-subproblem results are returned (see DMDO.architectures.mdf.run_mdf()).

MDO.coordinate(file=None, resume=False, mode=None, sweep=None, observers=None, should_stop=None)#

The coordination loop as a generator; run() and DMDO.Session drive it.

It yields two kinds of items:

  • a list of SubproblemTask: solve them and send back the list of SubproblemResult (any order; solve_task() solves one task);

  • an IterationEnd when an outer iteration is complete (send(None) to continue).

Parameters:

should_stop – called after each outer iteration; returning True ends the run there.

class DMDO.ProcessExecutor(max_workers=None)#

Bases: object

Runs tasks in a pool of worker processes; the pool is created lazily and reused across outer iterations.

Tasks and results are pickled, so blackboxes must be importable (module-level) callables. On Windows/macOS the calling script needs the usual if __name__ == "__main__": guard.

Parameters:

max_workers (Optional[int])
