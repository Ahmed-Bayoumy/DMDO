The basic problem from YAML#

This tutorial runs the basic two-discipline problem of Getting started from its YAML definition and walks through what DMDO prints and writes.

The problem#

\[\begin{split}\begin{array}{ll} \min_{u,v,w} & u + v + a + b \\[2pt] \text{s.t.} & a = \log_{10} u + \log_{10} v + \log_{10} b, \qquad b = u^{-1} + w^{-1} + a^{-1}, \\ & w + b - 10 \le 0, \qquad 0 \le u, v, w, a, b \le 10. \end{array}\end{split}\]

Subproblem 1 owns \(v\), computes \(a\) and holds the objective; subproblem 2 owns \(w\), computes \(b\) and holds the constraint; both keep copies of \(u\), \(a\) and \(b\) (see Background for the partitioned formulation).

The analyses#

examples/basic_disciplines.py writes the two analyses as Discipline objects (inputs and outputs keyed by variable name) and the subproblem objectives as plain functions:

import numpy as np


class Analysis1:
  """a = log10(u) + log10(v) + log10(b)"""

  def compute(self, inputs):
    u, v, b = (max(float(inputs[n]), 1e-12) for n in ("u", "v", "b"))
    return {"a": np.log10(u) + np.log10(v) + np.log10(b)}


class Analysis2:
  """b = 1/u + 1/w + 1/a"""

  def compute(self, inputs):
    u, w, a = (max(float(inputs[n]), 1e-12) for n in ("u", "w", "a"))
    return {"b": 1.0 / u + 1.0 / w + 1.0 / a}


def opt1(x, y, c=None):
  """Subproblem 1 objective: u + v + b + a (no constraint)."""
  return [sum(x) + y[0], [0.]]


def opt2(x, y, c=None):
  """Subproblem 2: no objective, constraint w + b - 10 <= 0."""
  return [0., [x[1] + y[0] - 10.]]


A1 = Analysis1()
A2 = Analysis2()

# Names used in basic_problem.yaml. Over the HTTP service, give them as import paths ("basic_disciplines:A1", ...).
BLACKBOXES = {"A1": A1, "A2": A2, "opt1": opt1, "opt2": opt2}

The highlighted lines are the settings that matter most:

  • every variable is declared REAL. OMADS optimizes variables of any other type on an integer lattice, so real variables must be declared with this exact keyword;

  • the coordinator uses \(\beta = 1.3\) and \(\gamma = 0.5\) with the normal update scheme, and scales the inconsistencies by 0.1 (one tenth, which is \(1/(u - \ell)\) for these bounds);

  • both subproblems are solved by the OMADS poll step with 150 evaluations per outer iteration.

Running it#

from basic_disciplines import BLACKBOXES
from DMDO import Session

if __name__ == "__main__":
    session = Session.from_yaml("basic_problem.yaml", working_dir="_runs", blackboxes=BLACKBOXES)
    result = session.run()
    print(result.status, "|", result.stop_reason)
    print(result.iterations, result.objective, result.max_inconsistency, result.feasible)

These values match, to every digit shown, the recorded regression run of this problem (basic_poll in Benchmarking), which builds the same problem with the Python API instead of YAML.

The max(w) column shows the penalty weights growing on the links that stall, from 1.3 to about \(6 imes10^{9}\); this growth is what eventually forces the copies together.

The output files#

The run writes its outputs to _runs/basic_problem_post:

_runs/basic_problem_post/
├── Coordination_history.out          one row per outer iteration
├── DMDO.log                          the log of the run
├── coord_chk.pkl                     checkpoint for resuming the run
└── coordination_summary_post/
    ├── SP_1/
    │   ├── SP_1_0.out ... SP_1_49.out   every evaluation of subproblem 1, per outer iteration
    │   └── OMADS.log
    └── SP_2/ ...

Coordination_history.out is a comma-separated table with, for each outer iteration, the time, the iteration number, the maximum inconsistency, the objective, the feasibility status, the change of the design, the largest penalty weight, the link with the largest inconsistency, the constraint violation of each subproblem and the value of every variable copy. It can be loaded with pandas.read_csv():

import pandas as pd

history = pd.read_csv("_runs/basic_problem_post/Coordination_history.out", skipinitialspace=True)
history.columns = history.columns.str.strip()
history.plot(x="Iteration #", y="Max. inconsistency", logy=True)
